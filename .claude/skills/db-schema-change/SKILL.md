# Changing the database schema

agent-kanban stores everything in one SQLite file (`~/.config/agent-kanban/db.sqlite` by default) via
Drizzle's `sqlite-proxy` driver wrapping `node:sqlite` (the official `node-sqlite` driver is only available
in Drizzle 1.0 beta, so this project is pinned to `sqlite-proxy`). Migrations are generated by `drizzle-kit`
and then bundled into a TypeScript module so the CLI package can run them without shipping raw `.sql` files.

## Steps

1. Edit `packages/core/src/db/schema.ts` (the Drizzle schema — tables, columns, indexes).
2. From the repo root, run:
   ```
   pnpm db:generate
   ```
   This runs `drizzle-kit generate` (writes SQL under `packages/core/drizzle/`) then
   `node --experimental-strip-types scripts/bundle-migrations.ts`, which regenerates
   `packages/core/src/db/migrations.generated.ts` — the file actually imported at runtime.
3. Do not hand-edit `migrations.generated.ts` or the generated `.sql` files under `packages/core/drizzle/` —
   they are build output; always change `schema.ts` and re-run `db:generate`.
4. Check `packages/core/src/db/migrate.ts` if the change needs anything beyond a plain column/table add
   (e.g. a data backfill) — Drizzle's generator only emits DDL, not data migrations.
5. Run `pnpm --filter @agent-kanban/core test` — `packages/core/src/db/db.test.ts` exercises the schema
   against a real `node:sqlite` database.
6. If any code reads/writes the changed table (`packages/core/src/store/`), update it and its zod schema in
   `packages/shared/src/` — `core` and `shared` types should stay in sync with the DB shape.

## Gotcha

Commit the generated `packages/core/drizzle/*.sql` and `migrations.generated.ts` files alongside the schema
change — they are checked in (not build artifacts ignored by git), since the CLI bundles them into the
published package.
